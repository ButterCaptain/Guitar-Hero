Note word encoding

One 16-bit word per note: 1 hold bit and a 15-bit frame number.

Claude says: A held end entry (hold bit 0) has the same bit pattern as a regular note. Your ignore logic is therefore required, and it needs one state flop, lastWasHoldStart. Set it when a word with hold = 1 is loaded and the flop was 0. When the flop is 1, treat the next word as the end marker and clear the flop. A more robust alternative is to widen the word to a 2-bit type field (regular, start, end) and use 14 bits for the frame number. The type then travels with the word and no state is needed.

Hit detection window

A note sits at frame 10. The FSM starts listening at frame − radius and stops at frame + radius. A strum is an edge, so each press of Strum registers once.

frame = 0   state = IDLE   pressednote = 0   score = 0

Step to the window, then press Strum while the fret is held.

Claude says: (1) The plan checks the fret when the strum edge occurs and latches pressednote. That is correct. The scoring line uses presseddown, which looks like a naming slip for pressednote. (2) No rule exists for a note that leaves the window without any strum. The end of the window already gives a trigger: if pressednote is 0 at end noteDetect, score down. The plan covers this with the else branch, so keep it. (3) Strums while a wrong fret is held should count as a miss. Compare the full 5-bit fret vector against the lane mask, not one fret. (4) Resolution is one display row. A faster tick for detection fixes this. (5) Held notes remain undefined. A simple model: strum at start window, fret must stay down until the end frame, add score each frame, release early ends the hold. (6) Add a synchronizer and debouncer on strum and frets before edge detection.
