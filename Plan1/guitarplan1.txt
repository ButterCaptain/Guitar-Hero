				(hardware needed to make sure that this note is ignored so that it doesn't continuously make more held notes)


Stored in on-chip memory, loading via mif file

mif file header looks like this (for example)
encodes the amount of notes in each lane and the start address for each lane (doesn't include effect lanes yet)

-- Note counts (lane 1..5)
0000 : 0014;
0001 : 0011;
0002 : 0016;
0003 : 0004;
0004 : 0005;
-- Lane start addresses (lane 1..5)
0005 : 000A;
0006 : 001E;
0007 : 002F;
0008 : 0045;
0009 : 0049;
